Scenario 1

React + Fluent UI v8/v9 + 1JS Ribbon

~1 day

What to do

  1. Upgrade React, Fluent UI v8/v9, and 1JS ribbon packages.
  2. Wrap the extension root with ExtensionThemeProvider from @trident/extension-client-theme.

Validation checklist

  • Package versions upgraded successfully.
  • ExtensionThemeProvider applied at app root.
  • Initial theme renders correctly (light & dark).
  • Runtime theme switching works without reload.
  • Key surfaces pass accessibility / contrast checks.

Code pattern

import { ExtensionThemeProvider } from '@trident/extension-client-theme';

function App() {
  return (
    <ExtensionThemeProvider>
      {/* your extension content */}
    </ExtensionThemeProvider>
  );
}
Scenario 2

Angular / Other iframe-Based Extensions

Varies

Shell APIs

APIPurpose
ExtensionClientAPI Entry point for all Shell extension APIs
themeAPI Exposes current theme & theme-change events

Key requirements

  • Detect current theme on load — don't assume light mode.
  • Listen for themeChanged events; re-apply immediately.
  • Avoid hard-coded colors; use design tokens.
  • Iframe updates without a full reload.

Code pattern

import { ExtensionClientAPI } from '@trident/extension-client';

const theme = ExtensionClientAPI
  .themeAPI.getCurrentTheme();
applyTheme(theme);

ExtensionClientAPI.themeAPI
  .onThemeChanged((newTheme) => {
    applyTheme(newTheme);
  });

Validation checklist

  • themeAPI in a single theme service.
  • Theme applied correctly on load.
  • onThemeChanged fires; UI updates without reload.
  • No hard-coded hex/rgb colors in styles.
Scenario 3

PBIClient-Based Repos

Varies

Current state

Dark mode is already enabled in the platform for PBIClient-based repos (e.g., Power BI). The main work is validation and legacy token cleanup.

What to do

  1. Run a full validation pass across core user journeys.
  2. Focus on: visual regressions, contrast, token mismatches, unreadable states.
  3. Leverage the AI tool provided by the Shell team to detect legacy tokens and get replacement suggestions.
  4. Keep a manual review step for edge cases and a11y-sensitive UI.

Effort scale

  • Few issues → short stabilization pass.
  • Many legacy token issues → additional fix-and-verify cycles.

Validation checklist

  • Full dark mode validation pass completed.
  • AI tool run; legacy token suggestions applied.
  • Manual review done for edge cases & a11y.
  • No blocking contrast or readability regressions.

Shared Validation Exit Criteria — All Scenarios

✓ No blocking contrast or readability issues.
✓ Theme switching works reliably at runtime.
✓ No major visual regressions in core user journeys.
✓ Accessibility checks pass for key surfaces.
