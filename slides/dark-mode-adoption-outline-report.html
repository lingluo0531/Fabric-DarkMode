Challenge: Multi-Semester Adoption Tail

  • Users navigate between workloads with mixed light and dark interfaces.
  • Inconsistent visuals reduce perceived platform polish.
  • The longer the tail, the higher the quality-perception risk.

Why the Tail Is Long

  • Competing priorities across workload teams and semester plans.
  • No unified deadline to force synchronized adoption.

1) Power BI

Risk: High
  • Status: Post-RB
  • Implementation Scope: Complex multi-component system
  • Technical Challenges:
    • Advanced editors depend on other components (Web modelling on PQO)
    • Reports define custom theming but may pull defaults from surrounding environment
    • Full component coverage remains unclear (semantic model settings pane status unknown)
  • Scope Clarity Issue: The full scope of work to support Dark Mode is not clear
  • Decision: Dark Mode is NOT in scope for RB semester
  • Top Priority: Clarifying scopes and timelines first
  • Next Steps: Organizing comprehensive testing on PBI pages to assess adoption gaps and inform post-RB acceleration decisions
  • Timeline: TBD (pending Waves roadmap clarification)

2) Data flow

Risk: High
  • Status: Post-RB
  • Implementation Scope: Self-hosted iframe architecture
  • Technical Blocker: Self-hosted iframes do not natively support dark mode and cannot use Shell-provided dark mode approach
  • Impact: Requires custom implementation; standard extension-based onboarding path not viable
  • Effort Level: High complexity; custom solution development required
  • Next Steps: Complex technical assessment required; solution approach still under evaluation
  • Timeline: TBD (pending technical feasibility assessment)

3) Data Activator

  • Blocker: None technical; availability dependent on team capacity
